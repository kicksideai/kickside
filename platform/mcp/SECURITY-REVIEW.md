# MCP security review

Scope: kickside/mcp 0.2.0 source, its HTTP endpoints, the application router wiring and the canonical execution identity boundary. Verification uses runtime dev-nightly-20261008-2bb9e14, fresh dependency resolution, SQLite and Postgres. All changes and merges stay local.

## Threat model

The adversary controls unauthenticated HTTP requests, Origin, OAuth registration metadata and authorization parameters. A credential holder controls JSON-RPC arguments, selected public traits and session identifiers. A separate user owns a disjoint component tree. A database reader can inspect credential and authorization-code rows. A proxy exposes a public authority different from the backend Host. Registry mutation, the runtime, the browser session store and the owner’s security policies remain trusted boundaries.

The protected assets are the approving user’s bearer credentials, component data, tool-result continuations and module administration capabilities. The MCP session identifier carries transport continuity, never identity. The bearer and current native security frame supply authority.

## Boundary checks

- Credentials use a CSPRNG token body and a SHA-256 lookup hash (`platform/mcp/src/persist/repo.lua:30`, `platform/mcp/src/persist/repo.lua:38`). SQL equality is not a constant-time raw-secret comparison. Random fixed-length token hashes supply no usable raw-prefix timing oracle; the review does not claim SQL provides constant-time comparison.
- Status and expiry apply at bearer resolution and protected credential reload (`platform/mcp/src/persist/repo.lua:198`). Every protected dispatch checks current Users status, pending policy fences and delegated epochs through canonical execution (`platform/mcp/src/security.lua:34`; `core/execution/src/execution_identity.lua:458`). Missing or inactive owners refuse execution. Direct and group access remain subject to the canonical component gate.
- An empty component whitelist retains whole-owner-tree semantics. A nonempty whitelist resolves component path prefixes and only narrows authority (`platform/mcp/src/persist/repo.lua:100`, `platform/mcp/src/persist/repo.lua:193`, `platform/mcp/src/persist/repo.lua:216`). Mint validates every requested component through the component service.
- The tool surface unions explicit tool grants with active public traits, bounded by allowed traits (`platform/mcp/src/surface.lua:97`). An empty trait ceiling preserves existing unrestricted public-trait discovery semantics. Continuation reads check credential, session and the continued tool’s current native permission and surface availability (`platform/mcp/src/dispatcher.lua:189`). Result content uses a 24 KiB window, with provenance retained by the contract result-window service (`platform/mcp/src/dispatcher.lua:56`). Native structured errors preserve their published payload contract.
- A supplied session id is validated as a bounded visible string and does not select a stored actor (`platform/mcp/src/api/serve_mcp.lua:32`). Possessing another session id without its bearer does not confer authority. Public initialize/ping expose protocol metadata; tools, resources and prompts require bearer admission.
- Module membership uses native module access policies and the authenticated router’s endpoint firewall. The app’s public CORS configuration allows the declared web-host origin rather than arbitrary origins (`app/src/app/registry/host/_index.yaml:12`). The MCP Origin boundary adds DNS-rebinding protection independently of CORS. Users management functions also check their native endpoint capability when called directly (`platform/users/src/api/create_user.lua:13`, `platform/users/src/api/update_user.lua:79`); module runtime function-call access does not by itself admit those management operations.
- The module performs no outbound HTTP fetch. Granted tools retain their native security frame and component restrictions; SSRF risks in a granted tool belong to that tool’s capability review. MCP denies registry/security/access administration and cross-user unscoped reads (`platform/mcp/src/security/_index.yaml:60`).
- The module has no logger invocation or raw-token audit writer. Management lists expose token prefixes, not raw credentials. Consent names a client through `textContent`, and state is percent-encoded in the callback. Lane evidence replaces raw bearers and authorization-code callback values with redacted markers.
- Refresh tokens are neither issued nor advertised. Refresh-token rotation is consequently inapplicable. Access expiry remains optional for compatibility with existing durable MCP credentials.

## Identity and session semantics

Login sessions retain native issuing policy ids. MCP captures the same public native policy-id representation for new credentials, together with issuing security groups and provider epochs. Users owns the durable epoch and advances it with access reduction, password/status mutation and deletion. Inherited execution compares required epochs after canonical status admission; restoration cannot reactivate a revoked credential. A newly authenticated issuing session can mint after restoration. Ordinary logout-all retains its current durable MCP behavior. No runtime-private token data is rewritten.

Existing legacy credentials have no recoverable issuing snapshot. They retain live-scope behavior until reissue and bind to the provider's initial epoch for future permanent reduction revocation. Historical pre-deployment reductions cannot be reconstructed from current membership. Custom providers that expose no optional epochs retain their existing behavior; a previously captured required epoch cannot disappear without refusing admission. A forward nullable credential column and a durable Users epoch table preserve stored data, ids and contracts.

## Abuse limits and deployment boundaries

New DCR registrations have a 64 KiB body bound, 256-character name, 16 callbacks of at most 2048 characters, 60 registrations per rolling minute and 10000 stored clients. Active credentials retain the existing per-owner cap of 100. Token exchange and MCP requests retain the native 120 MiB request-body bound and unchanged deadlines. Native structured tool errors retain their published payload contract. MCP has no additional per-bearer request throttle; HTTP traffic budgets and trusted-tool CPU budgets belong to the host and tool capabilities. The application process host bounds workers/processes. These controls bound storage and request size without claiming a general distributed denial-of-service guarantee.

TLS certificates and public listener configuration belong to the host/proxy. The forwarding proof uses loopback HTTP and configured public_api_url; it proves public authority selection and protocol flow, not production certificate issuance. Native callbacks remain an explicit compatibility extension relative to MCP's HTTPS/loopback wording. The module advertises protocol 2025-03-26; this review targets newer authorization requirements and does not claim complete 2025-06-18/2025-11-25 protocol support.
